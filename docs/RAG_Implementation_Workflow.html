Developer handoff • Proposed sequence

Build the RAG foundation, one working flow at a time

Approved school file → source-linked chunks → real vectors → authorized retrieval → Java-generated cited answer.

Starting position: your supplied guide describes health/readiness as wired; ingestion, retrieval repositories, and ORM migration wiring still require implementation. Progress below is manually entered, not repository verification.

First assignments: agree contracts, then work in parallel

Developer 1 — Contracts/security

Extend existing domain/schema contracts. Agree document/version/chunk/provenance/model scope with the founder. Required acceptance: valid payloads, explicit missing/null/empty permission behavior.

Developer 2 — Database

After contract agreement, implement ORM, forward migration and scoped repositories. Acceptance: disposable DB upgrade and real isolation tests.

Developer 3 — Document processing

After contract agreement, implement restricted text loading, extraction and conservative normalization. Acceptance: source mappings and English/Hindi/Odia fixtures preserved.

Founder reviews authorization, vector compatibility, lifecycle, evaluation labels, and release evidence. Interns own bounded fixtures, extractors, tests and documentation with review.

Milestone demonstrations

  1. Document pipeline: show circular, cleaned blocks and source-linked chunks.
  2. Indexed document: show vectors and active published revision.
  3. Durable ingestion: stop/restart worker; safe completion.
  4. Authorized retrieval: correct school-timing evidence; deny another tenant.
  5. Measured retrieval: baseline metrics and actual failures.
  6. Parent Q&A: Java cites support or returns no-answer.
  7. Release candidate: outage, revocation, failed reindex, restore and load behavior.

Golden-question preparation, security tests, source-rights checks, logging and observability begin early and continue through every step.
