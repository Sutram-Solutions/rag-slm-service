Tenant-safe reference rule

A child must reference the parent through tenant/collection plus ID, not only a globally unique UUID. Referenced tuples need UNIQUE or PK constraints. This prevents a School A row linking to a School B document. It does not prove the caller may read the row: scoped SQL and role/RLS tests still required.

Deletion and history

Baseline foreign keys default to RESTRICT/NO ACTION; do not cascade away source evidence accidentally. Retention service deletes embeddings → chunks → retired revisions, then permitted source versions/storage in explicit order. Publication/job references must be resolved first. Soft-delete is not physical deletion. Historical source access is a separate authorization/lifecycle policy; current publication pointer alone cannot implement it.

Model → ORM → table mapping

Document → DocumentRecord → documents; DocumentVersion → DocumentVersionRecord → document_versions; CollectionConfiguration → configuration record; EmbeddingModelSpec → specification record; ChunkDraft/provenance → chunk row plus validated JSONB; IngestionJob → job row. RetrieveRequest/Response, ErrorResponse and ReadinessResponse are transfer models, not automatically database tables. AuthorizationScope is a request value; document_acl stores resource grants, not copied parent request scopes.

Join logic for retrieval

Start with document_publications.active_index_revision_id; join eligible approved source/index/config/spec and chunks/embeddings. Apply tenant + allowed collection + matching resource grant + optional document allow-list + denied IDs + effective/expiry/deletion predicates before candidate LIMIT. Embed query using that exact spec; never compare unrelated spaces.

Required verification

  • Clean migration and upgrade from existing supported revision.
  • Cross-tenant foreign-key insert and read denial.
  • Missing/null/empty permission behavior in repository and API.
  • Vector finite/dimension/spec compatibility; no wrong-space comparison.
  • Failed staging build leaves prior publication active.
  • Concurrent idempotency duplicate and conflicting payload.
  • Expired worker token cannot finalize/publish.
  • Application role/RLS and pooled tenant context isolation.
  • Expired/unpublished/deleted source excluded; historical policy tested separately.
  • Backups/restore, deletion, migration downgrade destructive effects documented.
